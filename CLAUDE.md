# DBPs Regression Pipeline - Claude Notes

## Project Overview

This is a machine learning backend for analyzing dissolved by-product (DBP) sensor data. It provides an end-to-end toolkit for training multi-output regressors including MLP, LSTM, RNN, GRU, Transformer, Mamba, XGBoost, LightGBM, and CatBoost.

## Architecture

### Core Components

```
├── data/              # Raw, imputed, and aligned CSV files
├── models/            # PyTorch model implementations and configs
│   ├── configs/       # TOML configuration files
│   ├── mlp_regressor.py
│   ├── lstm_regressor.py
│   ├── rnn_regressor.py
│   ├── gru_regressor.py
│   ├── transformer_regressor.py
│   ├── mamba_regressor.py
│   ├── xgboost_regressor.py
│   ├── lightgbm_regressor.py
│   └── catboost_regressor.py
├── scripts/           # Training, testing, and utility scripts
│   ├── train.py
│   ├── test.py
│   ├── autotune.py
│   ├── split_data.py
│   ├── server.py
│   └── utils.py
└── outputs/           # Training outputs and results
```

### Model Types

**PyTorch Models (Neural Networks):**
- `MLP` - Multi-Layer Perceptron with configurable hidden layers
- `LSTM` - Long Short-Term Memory networks for sequence modeling
- `RNN` - Simple Recurrent Neural Networks
- `GRU` - Gated Recurrent Units
- `TRANSFORMER` - Encoder-only Transformer architecture
- `MAMBA` - State Space Model (SSM) with selective scanning

**GBDT Models (Gradient Boosting):**
- `XGBOOST` - eXtreme Gradient Boosting
- `LIGHTGBM` - Light Gradient Boosting Machine
- `CATBOOST` - Categorical Boosting

## Configuration System

### Base Config Format (TOML)

All models use a unified TOML configuration format:

```toml
[model]
type = "LSTM"
name = "lstm_regressor"
history_length = 32
units = 128
num_layers = 2
dropout = 0.2

[training]
max_epochs = 100
batch_size = 128
learning_rate = 0.001
weight_decay = 0.0
patience = 10
seed = 42

[data]
train_csv = "data/train.csv"
val_csv = "data/val.csv"
test_csv = "data/test.csv"
input_columns = ["TRC-DT", "pH-DT", "cond-DT", "TRC-RT", "pH-RT"]
output_columns = ["TRC-PPL1", "TRC-PPL2", "pH-PPL1", "pH-PPL2"]
```

### Bayesian Optimization Config

Bayesian search spaces are defined in separate `*_bayes.toml` files:

```toml
[parameters.history_length]
min = 32
max = 160
step = 8
log = false

[parameters.units]
min = 64
max = 384
step = 8
log = false

[parameters.dropout]
min = 0.1
max = 0.5
log = true

[parameters.batch_size]
min = 64
max = 384
step = 4
log = false

[parameters.learning_rate]
min = 0.0002
max = 0.002
log = true

[parameters.weight_decay]
min = 0.0001
max = 0.01
log = true
```

## Usage

### 1. Split Data

```bash
python scripts/split_data.py \
    --input data/imputed_data.csv \
    --train-ratio 0.7 \
    --val-ratio 0.15 \
    --test-ratio 0.15 \
    --output-dir data \
    --seed 42
```

### 2. Train a Model

```bash
python scripts/train.py --config models/configs/rnn_config.toml
```

### 3. Run Bayesian Optimization

```bash
python scripts/autotune.py \
    --model-type RNN \
    --base-config models/configs/rnn_config.toml \
    --bayes-config models/configs/rnn_bayes.toml \
    --n-trials 100
```

### 4. Test a Trained Model

```bash
python scripts/test.py --model-dir outputs/rnn_regressor/<timestamp>
```

### 5. Comprehensive Experiment (All Models)

```bash
python scripts/run_comprehensive_experiment.py \
    --input data/imputed_data.csv \
    --output-dir outputs/comprehensive_experiment \
    --n-trials 100 \
    --models all
```

## Model-Specific Notes

### Mamba Model

The Mamba implementation is a simplified pure-PyTorch version that doesn't require the `mamba-ssm` package. It implements:
- Selective state space model with input-dependent parameters
- Convolutional filtering
- Gating mechanisms
- Residual connections

For production use with the full Mamba implementation, install `mamba-ssm` and modify the imports.

### Transformer Model

The Transformer uses an encoder-only architecture with:
- Positional encoding
- Multi-head self-attention
- Feed-forward layers
- Layer normalization
- Dropout regularization

### GBDT Models

XGBoost, LightGBM, and CatBoost are trained per-target (one model per output column). This allows each target to have its own optimized model.

## Data Format

Input CSV files should have the following columns:
- `Date, Time` (optional): Timestamp column
- Sensor readings: `TRC-DT`, `TRC-RT`, `TRC-PPL1`, `TRC-PPL2`, etc.
- Derived features: `minutes_since_start` (auto-generated by data loader)

## New Datasets

Three new datasets have been added (CAWW_35C, LSWW_29C, LSWW_35C) with the same sensor structure as the original CAWW_29C dataset. These datasets are available in the `data/` directory:

- `CAWW_35C_DT_full.xlsx` → `caww_35c_raw_data.csv` → `caww_35c_imputed_data.csv`
- `LSWW_29C_DT_full.xlsx` → `lsww_29c_raw_data.csv` → `lsww_29c_imputed_data.csv`
- `LSWW_35C_DT_full.xlsx` → `lsww_35c_raw_data.csv` → `lsww_35c_imputed_data.csv`

Each dataset has been split into train/val/test (70:15:15) in respective `*_split/` directories.

### Processing New Datasets

Use `scripts/process_all_new_datasets.py` to convert Excel files to CSV, run imputation, and split data:

```bash
python scripts/process_all_new_datasets.py
```

## Fine-Tuning on New Datasets

Two fine-tuning approaches are supported for transferring models trained on the original dataset to new datasets:

1. **Full Fine-Tuning**: Update all model parameters with a lower learning rate
2. **Partial Fine-Tuning**: Freeze early layers, only update later layers

Use `scripts/fine_tune_transformer.py` for fine-tuning Transformer models on new datasets.

## Output Structure

Training outputs are saved to `outputs/<model_name>/<timestamp>/`:
- `best_model.pt` - Best model checkpoint (PyTorch)
- `last_model.pt` - Final model checkpoint
- `scalers.npz` - Feature scaling parameters
- `config.toml` - Copy of training configuration
- `result.toml` - Training results and metrics
- `loss_history.csv` - Per-epoch loss values
- `training_curve.png` - Loss visualization

## Troubleshooting

### CUDA Out of Memory
- Reduce `batch_size` in config
- Reduce `units` or `hidden_size`
- Use gradient accumulation (requires code modification)

### Poor Convergence
- Increase `learning_rate` (start with 0.001)
- Increase `max_epochs`
- Reduce `patience` for early stopping
- Check data scaling (should be normalized)

### Slow Training
- Use GPU if available
- Reduce `history_length` for sequence models
- Reduce `n_trials` for bayesian optimization
- Use smaller `batch_size` (may be counter-intuitive but can be faster on GPU)
